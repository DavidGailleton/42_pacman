# Pac-Man — Ghosts! More ghosts

## Description

A complete, playable Pac-Man written in Python with an object-oriented,
modular architecture.

- Mazes are generated by the **A-Maze-ing** package of 42 (`mazegenerator-00001.zip`), used as-is.
- Graphics use **pygame**, restricted to functions that have an MLX
  equivalent (window, filled shapes, lines, text, key events).
- 4 ghosts, each with its own chasing strategy, that become edible after
  a super-pacgum.
- Several levels with a time limit; score and lives carry over.
- Persistent top-10 highscores, pause menu and a cheat mode for reviewers.
- Everything is configured through a JSON file (with `#` comments), and
  any faulty value is replaced by a safe default instead of crashing.

## Instructions

### Requirements

- Python 3.10 or newer
- [uv](https://docs.astral.sh/uv/)

### Install

```bash
make unzip_maze   # only if lib/ does not contain the mazegenerator wheel yet
make install      # uv sync: pygame, pydantic, mazegenerator + dev tools
```

### Run

```bash
uv run python3 pac-man.py config.json
# or
make run ARGS=config.json
```

The game takes **exactly one argument**: the path of the configuration
file. A wrong number of arguments, a missing file or invalid JSON prints
a clear error message and exits with status 1 (never a traceback).

### Controls

| Key                 | Action                                     |
| ------------------- | ------------------------------------------ |
| Arrow keys / WASD   | Move Pac-Man, navigate menus               |
| Enter               | Select a menu entry / confirm your name    |
| Esc                 | Pause / resume (or go back from a screen)  |
| C                   | Toggle cheat mode (invincible)             |
| N                   | Skip to the next level (cheat mode only)   |

### Rules

- Eat every pacgum, **or** survive until the level timer runs out, to
  clear a level.
- The 4 super-pacgums are in the maze corners. Eating one makes every
  ghost edible (blue) for 7 seconds.
- An eaten ghost goes back to its corner and comes back after 5 seconds.
- Touching a chasing ghost costs a life: Pac-Man and the ghosts go back
  to their start positions. At 0 lives, the game is over.
- After the last level (or a game over), the end screen shows the final
  score and asks for your name to save it in the highscores.

### Packaging

The game is packaged as a standalone Linux executable with
[PyInstaller](https://pyinstaller.org). The build spec is `pac-man.spec`.

```bash
make package
```

This creates `release/pac-man-linux.tar.gz`, which contains:

- `pac-man`: the executable (Python is not needed to run it)
- `config.json`: the configuration file, which you can edit
- `run.sh`: a launcher that runs `./pac-man config.json`
- `INSTRUCTIONS.txt`: how to play

Only a Linux build is provided, because PyInstaller can't cross-compile.

Published build: [https://davidgailleton.itch.io/42-pacman](https://davidgailleton.itch.io/42-pacman)

## Configuration

The configuration file is JSON **with comments**: any line whose first
non-blank character is `#` is ignored (`strip_comments` in
`src/config_loader.py`).

| Key                      | Type                    | Default             | Valid values                            |
| ------------------------ | ----------------------- | ------------------- | --------------------------------------- |
| `highscore_filename`     | string                  | `"highscores.json"` | non-empty path                          |
| `levels`                 | list of `{width, height}` | 10 levels of 21×21 | at least 10 levels; width/height 10 – 100 |
| `lives`                  | integer                 | `3`                 | 1 – 99                                  |
| `point_per_pacgum`       | integer                 | `10`                | ≥ 0                                     |
| `point_per_super_pacgum` | integer                 | `50`                | ≥ 0                                     |
| `point_per_ghost`        | integer                 | `200`               | ≥ 0                                     |
| `seed`                   | integer                 | `42`                | any; ≤ 0 gives random mazes             |
| `level_max_time`         | integer (seconds)       | `90`                | ≥ 1                                     |

- `levels` are played in order; the game is won after the last one.
- Each level is checked on its own: an invalid level is replaced by a
  21×21 level, and if fewer than 10 levels are given, 21×21 levels are
  added at the end (with a warning).
- Types are strict: `"3"` or `true` are not accepted where an integer is
  expected.
- A missing or invalid value is replaced by its default and a warning is
  printed in the terminal; the game still starts.
- Unknown keys are ignored.
- A file that cannot be read or is not valid JSON stops the program with
  an error message (status 1).

Example:

```
# Pac-Man configuration file (lines starting with # are ignored)
{
  "highscore_filename": "highscores.json",
  # One maze size per level, played in order
  "levels": [
    { "width": 15, "height": 15 },
    { "width": 21, "height": 21 }
  ],
  "lives": 3,
  "point_per_pacgum": 10,
  "point_per_super_pacgum": 50,
  "point_per_ghost": 200,
  # Seed of level 1; the next levels are random
  "seed": 42,
  "level_max_time": 90
}
```

## Highscore

Highscores are handled by `src/score_management.py`.

- Stored in the file named by `highscore_filename`, relative to the
  directory the game is launched from, as a JSON list:
  `[{"name": "PLAYER", "score": 1234}, ...]`.
- Only the **10 best** scores are kept, sorted from best to worst; on a
  tie, the older entry stays ahead.
- Names: 1 to 10 characters, letters, digits and spaces only.
- Scores: non-negative integers.
- Loaded when the highscore screen opens, saved on the end screen when
  the player confirms their name.
- Robustness: a missing file gives an empty table; an unreadable or
  corrupt file, or a file that is not a list, is ignored with a warning;
  invalid entries are skipped one by one, so a single bad line does not
  lose the whole table.

## Maze Generation

Mazes come from the external **A-Maze-ing** package (`mazegenerator`
2.1.0, installed from `lib/mazegenerator-2.1.0-py3-none-any.whl`). It is
used **unmodified**: the only code that talks to it is the adapter class
`Maze` in `src/utils/maze.py`.

- The adapter calls
  `MazeGenerator(size=(width, height), seed=seed, perfect=False)`.
  `perfect=False` adds loops, so the player can escape the ghosts.
- Any exception raised by the generator is caught and re-raised as a
  `RuntimeError` with a clear message, which the entry point prints
  without a traceback.
- Each cell is an integer bitmask of its walls: `NORTH = 1`, `EAST = 2`,
  `SOUTH = 4`, `WEST = 8` (`src/constants.py`). The adapter exposes
  `can_move(cell, direction)` and `is_closed(cell)` so the rest of the
  game never reads raw bits.
- The generator draws a "42" pattern made of closed cells (4 walls).
  These cells get no pacgum, and Pac-Man starts on the open cell nearest
  to the maze center.
- Seeds: level 1 uses `seed`, so it is always the same maze. The next
  levels use seed `0`, which makes the generator pick a random maze, so
  they change every game. A `seed` ≤ 0 makes level 1 random too.

## Implementation

- **Game loop** (`src/app.py`): fixed 60 FPS. Every timer counts
  `FRAME_TIME` (1/60 s) per frame instead of real time, so movement and
  timers stay in sync even on a slow machine.
- **Pac-Man movement** (`src/layouts/game.py`): grid-based, 10 frames
  per cell. The last key pressed is buffered and applied at the next
  cell center where it is possible; turning back is allowed at any time.
- **Ghost AI** (`src/ghost_ai.py`): an abstract `Ghost` class holds the
  shared logic (position, state, timers, path-finding with a BFS from
  `src/utils/bfs.py`). Each subclass only chooses its chase target:
  - **Blinky** (red): Pac-Man's cell;
  - **Pinky** (pink): 4 cells ahead of Pac-Man;
  - **Inky** (cyan): flanks Pac-Man using Blinky's position;
  - **Clyde** (orange): chases from afar, goes back to his corner when
    closer than 8 cells.

  Ghosts are slightly slower than Pac-Man (12 frames per cell). States:
  `CHASE` → `FRIGHTENED` (runs to its corner, edible) → `EATEN` (waits
  5 s in its corner) → `CHASE`.
- **Collisions** (`src/utils/collision.py`): Pac-Man and a ghost collide
  when their centers are closer than 0.5 cell. Eating a ghost freezes
  the game for 0.2 s.
- **Pacgums** (`src/models/pacgum.py`): one pacgum on every open cell,
  a super-pacgum in each corner. The score only ever increases.
- **Cheat mode**: `C` makes Pac-Man invincible; "CHEAT MODE" is shown in
  red in the HUD. While it is on, `N` skips to the next level (after the
  last one, the game is won).
- **Error handling**: config and highscore errors are handled where they
  happen; `main()` in `src/__main__.py` also catches any remaining
  exception and prints it, so no traceback ever reaches the player.
- **Code quality**: type hints everywhere, docstrings (Google style),
  `make lint` with zero errors, unit tests in `tests/`.

## General Software Architecture

```
pac-man.py              entry point: python3 pac-man.py config.json
src/
├── __main__.py         argument check, config loading, error handling
├── app.py              App: window, game loop, current layout
├── config_loader.py    read file, strip comments, decode JSON
├── constants.py        sizes, speeds, colors, wall bits, directions
├── ghost_ai.py         Ghost base class + Blinky, Pinky, Inky, Clyde
├── score_management.py highscore load / save
├── models/             data and rules
│   ├── config.py       pydantic Config model with safe defaults
│   └── pacgum.py       pacgum and super-pacgum placement / eating
├── layouts/            one class per screen
│   ├── layout.py       abstract Layout
│   ├── menu.py         reusable keyboard menu
│   ├── main_menu.py, game.py, pause_menu.py, end_screen.py,
│   └── highscore_screen.py, instructions_screen.py
├── renderer/           drawing only, no game logic
│   ├── maze_renderer.py, pacman_renderer.py, ghost_renderer.py,
│   └── pacgum_renderer.py, hud_renderer.py, draw_utils.py
└── utils/
    ├── maze.py         adapter around the A-Maze-ing package
    ├── bfs.py          shortest path in the maze grid
    └── collision.py    distance-based collision test
tests/                  pytest unit tests + faulty configs (tests/test_configs/)
packaging/              run.sh and INSTRUCTIONS.txt for the release
pac-man.spec            PyInstaller build spec
```

**Screens as states.** Every screen inherits from `Layout` and
implements `handle_event`, `update` and `draw`. `handle_event` and
`update` return the layout to show next, so `App.run` only has to swap
`self.layout`; there is no global state machine.

```
            ┌──────────────► Highscores ──┐
            │                             │ Esc
 MainMenu ──┼──────────────► Instructions ┤
    ▲       │                             │
    │       └─ Start ─► Game ◄──Resume──► PauseMenu ──Main menu──┐
    │                    │                                       │
    │                    └─ game over / victory ─► EndScreen     │
    │                                               │ Enter      │
    └───────────────────────────────────────────────┴────────────┘
```

**Logic vs drawing.** Models (`Maze`, `Pacgum`, `Ghost`, `Config`) know
nothing about pygame; renderers read them and draw. This keeps the logic
unit-testable and makes the graphics layer easy to swap for MLX.
